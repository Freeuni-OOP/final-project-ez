# AlgoRythm

**AlgoRythm** არის მუსიკალური პლატფორმა, რომელიც მომხმარებელს საშუალებას აძლევს, ტექსტური პატერნებით შექმნას, შეინახოს და გააზიაროს მუსიკალური კომპოზიციები.

მომხმარებელი წერს ინსტრუმენტებისა და ნოტების თანმიმდევრობას შესაბამისი სინტაქსით, უშვებს კომპოზიციას და ისმენს შედეგს.

პროექტი შექმნილია როგორც **Object-Oriented Programming-ის ფინალური პროექტი**.

---

## ძირითადი შესაძლებლობები

AlgoRythm-ში მომხმარებელს შეუძლია:

- შექმნას და შეინახოს საკუთარი კომპოზიციები.
- გამოაქვეყნოს კომპოზიცია და გააზიაროს მისი ბმული.
- `Explore` გვერდზე დაათვალიეროს სხვა მომხმარებლების ნამუშევრები.
- მოძებნოს და თეგების მიხედვით გაფილტროს საჯარო კომპოზიციები.
- მოიწონოს კომპოზიციები და დატოვოს კომენტარები.
- გამოიწეროს სხვა ავტორები.
- `Feed`-ში ნახოს გამოწერილი ავტორების ახალი ნამუშევრები.
- მართოს საკუთარი ანგარიში:
  - შეცვალოს ელფოსტა.
  - შეცვალოს პაროლი.
  - წაშალოს ანგარიში.

## ლოკალურად გაშვება

### მოთხოვნები

პროექტის გასაშვებად საჭიროა მხოლოდ:

- Docker.
- Docker Compose.

Java-ს, Node.js-ისა და PostgreSQL-ის ცალკე დაყენება საჭირო არ არის, ყველა კომპონენტი Docker-კონტეინერში ეშვება.

### პროექტის გაშვება

პროექტი მთავარ საქაღალდეში ეშვება:

```bash
docker compose up --build
```

პირველი გაშვება შესაძლოა შედარებით დიდხანს გაგრძელდეს, რადგან Docker საჭირო იმიჯებს ააწყობს. მომდევნო გაშვებები უფრო სწრაფი იქნება.

### ხელმისაწვდომი მისამართები

სერვისების გაშვების შემდეგ გახსენით:

- Frontend: <http://localhost:3000>
- Backend API: <http://localhost:8080>

### პროექტის გაჩერება

აქტიურ ტერმინალში დააჭირეთ:

```text
Ctrl+C
```

კონტეინერების სრულად გასაჩერებლად გაუშვით:

```bash
docker compose down
```

## მუსიკალური პატერნის სინტაქსი

თითოეული ხაზი წარმოადგენს ერთ ტრეკს და შედგება ორი ნაწილისგან:

```text
instrument: sequence
```

- ორწერტილის მარცხნივ იწერება ინსტრუმენტის სახელი.
- მარჯვნივ იწერება ნაბიჯების თანმიმდევრობა.
- თითოეული ტოკენი წარმოადგენს ერთ იტერაციას.
- `-` აღნიშნავს პაუზას, ანუ სიჩუმეს.

### მაგალითი

```text
drum: kick - kick - kick - kick -
drum: - hat - hat - hat - hat
bass: C2 - C2 - G1 - G1 -
```

დრამის ტოკენები, მაგალითად `kick`, `hat` და `clap`, პერკუსიულ ხმებად გარდაიქმნება.  
ნოტები, მაგალითად `C4` ან `F#5`, შესაბამის სიხშირეებად მუშავდება და მელოდიის სახით ჟღერს.

სინტაქსის დამატებითი დეტალები ხელმისაწვდომია აპლიკაციის **Syntax Guide** გვერდზე.

## პროექტის სტრუქტურა

```text
.
├── src/                    # Frontend application
│   ├── routes/             # Application pages and routes
│   └── lib/
│       └── api.ts          # Backend API integration
├── backend/                # Spring Boot backend
│   └── src/main/java/      # Java source code
├── docker-compose.yml      # Frontend, backend and database orchestration
└── README.md
```

Backend დაყოფილია პასუხისმგებლობების მიხედვით:

- `controller`: HTTP მოთხოვნების დამუშავება.
- `service`: ბიზნესლოგიკა.
- `repository`: მონაცემთა ბაზასთან ურთიერთობა.
- `model`: დომენისა და მონაცემთა მოდელები.

## კონფიგურაცია

ლოკალური განვითარების გარემოში საჭირო პარამეტრებს ნაგულისხმევი მნიშვნელობები აქვს, ამიტომ დამატებითი კონფიგურაცია აუცილებელი არ არის.

Production გარემოში JWT-ის API KEY აუცილებლად უნდა შეიცვალოს გარემოს ცვლადის საშუალებით:

```bash
APP_JWT_SECRET=your-secure-secret
```

საიდუმლო გასაღები არ უნდა ინახებოდეს Git-ის რეპოზიტორიაში.

პირველი ადმინისტრატორის დასაყენებლად გამოიყენეთ გარემოს ცვლადი `APP_ADMIN_USERNAMES` (მძიმეებით გამოყოფილი მომხმარებლის სახელები). აპლიკაციის გაშვებისას მითითებული მომხმარებლები ავტომატურად მიიღებენ ADMIN როლს:

```bash
APP_ADMIN_USERNAMES=your-username
```
